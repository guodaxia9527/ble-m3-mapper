## 手机 App

- 六键可配置前进／后退、播放／暂停、字幕导航、转写文稿开关、点赞和不执行。
- YouTube 左右键在转写文稿打开时导航上一句／下一句；普通播放页面按自定义秒数跳转（默认 ±10 秒）。
- YouTube 中键设为播放／暂停时，单击播放／暂停，320ms 内双击点赞且不切换播放状态；
  第六键开关转写文稿。文稿入口已适配当前 YouTube 的“内容转文字”，在竖屏视频详情页使用。
- 文稿导航读取真实字幕时间后调用播放器精确跳转，不依赖点按字幕行坐标；
  当前真机单次查找和跳转确认约 0.1 秒，收起键盘时约 0.5 秒（不含蓝牙和前台检查）。
  文稿面板首次展开仍需等待 YouTube 加载，本轮实体测试打开约 2.3 秒。
- 0.1.15-test 已安装，用户确认第六键开关、中键单击、双击点赞均正常。
  升级保留自定义秒数和其他 App 配置，并在修改配置前留存一份本地偏好备份。
- 默认 YouTube：上后退5秒、下前进5秒、左右自适应字幕／10秒跳转、中键播放／暂停，
  第六键开关转写文稿。
- 可按 App 保存独立方案，支持从已安装应用列表选择，或输入精确包名；可删除当前方案。
  删除会立即保存，运行时会更新剩余方案；删除最后一个方案会停止映射，重新打开 App 后仍为空。
- 点赞本轮仅适配 YouTube，通过媒体评分接口设置赞，不切换或取消赞。
  播放器明确回传已赞时可跳过请求；未回传确认时只提示已发送请求，需要在 YouTube 中核对。
- 只在已配置的 App 位于前台且屏幕解锁时接管遥控器。
  离开该 App 或锁屏后约0.5秒释放，切回后重新接管；每次按键会再检查前台应用。
- 蓝牙断连后等待重连；运行不再限制10分钟。通知栏和主页都可停止。
- 当前是媒体控制版本。其他 App 需要提供对应 MediaSession 能力才能跳转／播放；
  目前只有 YouTube 实测，通用点击／滑动尚未实现。

权限和首次使用：

1. 在系统蓝牙连接 BLE-M3。
2. 安装并启动[官方 Shizuku](https://shizuku.rikka.app/download/)，在本 App 授权。
   Android 11+ 可用无线调试启动；每次手机重启后需再次启动 Shizuku。
   首次配对后，可从 Shizuku 应用通过无线调试启动；每次重启手机后需重新启动服务。
3. 某些厂商系统可能限制 Shizuku 的 ADB 权限；请参考 Shizuku 针对设备的说明。
4. 电脑 USB 启动方式可能受手机 USB 模式影响；日常使用建议通过 Shizuku 无线调试启动。
5. 本 App 点击“开始使用”，允许通知可显示运行状态和停止按钮。
6. 打开 YouTube 视频，播放几秒使媒体会话就绪，再使用遥控器；正常操作无需电脑。

当前不需要无障碍、通知读取、存储、定位或蓝牙扫描权限；系统已负责蓝牙配对，
Shizuku 提供输入接管及媒体控制权限。字幕跳转复用映射期间的 shell 界面会话，
不要求用户额外启用无障碍服务。本 App 没有网络权限。
若厂商后台限制导致映射停止，再在系统应用管理中允许后台运行；当前没有自动修改电池设置。
构建和真机检查详见 [验证记录](android-app/VALIDATION.md)。

### 手机上重新启动

1. 连接 Wi-Fi，在开发者选项开启“无线调试”。
2. 打开 Shizuku，点“通过无线调试启动”下的“启动”，等到显示“正在运行”。
3. 回到“遥控映射”，点“开始使用”，再打开 YouTube。

首次配对时，请在系统无线调试页面按 Shizuku 的提示完成配对，并允许 Shizuku 通知。

当前版本需要分别安装 Shizuku 和遥控映射。Shizuku API 依赖仅为客户端，
单 APK 需要另行整合无线 ADB 配对、激活及本应用专用的高权限后台；
这不会消除首次授权、开发者选项及手机重启后重新激活的要求。

手机工程构建（已安装 JDK、SDK、NDK 28.2.13676358）：

```powershell
$env:JAVA_HOME = 'C:\Program Files\Android\Android Studio\jbr'
$env:ANDROID_HOME = "$env:LOCALAPPDATA\Android\Sdk"
cd android-app
```

输出 `android-app/app/build/outputs/apk/debug/app-debug.apk`，目前为本机调试签名测试版。
仅打包 ARM64 原生程序。Android 13 真机验证，其他系统／厂商尚待验证。

## 电脑联机原型：映射

| 按钮 | 操作 |
|---|---|
| 上 | 后退 5 秒（到达开头时截断） |
| 下 | 前进 5 秒（到达结尾时截断） |
| 左 | 后退 10 秒 |
| 右 | 前进 10 秒 |
| 中 | 播放／暂停 |
| 第六键 | 已识别，暂不分配 |

此节描述保留的电脑联机原型，其第六键仍为 `none`，与手机 App 0.1.3 的点赞默认值不同。
映射保存在 `config/profiles.json`。每个 App 按精确包名有独立方案，
支持 `seek`（-300～300 秒）、`toggle`、`none`；其它动作尚未实现。
桥接会按当前焦点 App 选方案，媒体帮助程序只控制该包名的会话。
其它 App 的实际媒体控制能力需逐个验证，目前仅 YouTube 已实测。
该联机原型接管期间，未配置 App 上的遥控器输入会被忽略；
手机 App 已另行实现离开配置 App 后自动释放接管、恢复原行为。

原生程序只独占 `BLE-M3 Mouse` 和 `BLE-M3 Consumer Control`，不读取手机触屏或电脑键盘。
接管期间其原来的鼠标手势不会交给普通应用。结束、进程关闭或断开时释放。
第六键同时发送鼠标点击和音量加／减报告；合并两接口数据后判为 PHOTO，
其默认 `none` 配置不会改变播放或音量。最后五次第六键已用真实记录回放确认。
左右键分别产生 dx=450 与 dx=-450 的拖动，已确认可区分。
当前配置仅包含 `com.google.android.youtube`，联动仅在配置中的 App 有焦点时执行。
整个测试最多 600 秒（包括等待设备）；启动和运行中均会等待蓝牙重新连接，
重连后丢弃未完成手势并重新接管两接口。

## 电脑联机原型：编译与运行

电脑已安装的 Android SDK、NDK 28.2、JDK 和 Python 即可使用。
启用手机 USB 调试、授权电脑、在手机系统蓝牙中连接遥控器，然后打开并暂停一段 YouTube 视频。

```powershell
.\tools\build_and_deploy.ps1 -Serial DEVICE_SERIAL
python .\tools\run_bridge.py --adb "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" --serial DEVICE_SERIAL --seconds 300
```

输出 `BRIDGE_READY` 后按键。日志保存在 `logs/`，记录识别动作、请求位置和实际位置。
在运行终端按 Ctrl+C 结束，或等待时限。脚本会关闭辅助程序并释放遥控器。

此联机脚本部署只写入手机 `/data/local/tmp/ble_m3_capture` 和
`/data/local/tmp/ble-youtube-control.jar`，不安装 APK、不修改固件、不取得 Root。
手机 App 则单独安装 APK 及官方 Shizuku，也无需 Root。
Java helper 使用 Android 13 的内部初始化接口；其它系统版本需要另行验证。
